# Cloud Concepts: Why the Cloud

Most of your work today happens on-premises — servers you can point at, in a building you can walk
into. This module explains what changes when computing becomes a **service** you rent instead of
hardware you own: what "the cloud" actually is, the models for buying it, the models for deploying
it, why organizations move (and what it costs), and — for a government setting especially — how
**data residency, sovereignty, and compliance** shape what you're allowed to do.

It is deliberately vendor-neutral and conceptual. The goal is fluency in the vocabulary and the
trade-offs, so that when someone says "we'll put that in a managed service in the gov cloud region"
you know exactly what was, and wasn't, decided.

## What you'll learn

| # | Lesson | Idea |
|---|---|---|
| 01 | What the cloud actually is | On-demand, self-service computing rented as a service — the defining characteristics |
| 02 | Service models | IaaS / PaaS / SaaS — how much you operate vs how much is operated for you |
| 03 | Deployment models | Public / private / **hybrid / on-prem**, and sovereign / government clouds |
| 04 | Why cloud — benefits & economics | Elasticity, managed operations, pay-as-you-go — and the trade-offs |
| 05 | Governance, security & sovereignty | Data residency, compliance, and the shared-responsibility model |

**Total: ~1 hour.**
