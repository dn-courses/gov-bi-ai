## Who may call it

Cloud Run checks every request before your code sees it. The instructor sends two requests to
`agent-preview`, one with no token and one with an identity token, and you follow on the projector:
the answers recorded on 2026-11-23 were 403, then 200. Run the two cells with your own account and
you get 403 both times, because no one has granted your account the right to invoke the service.

```python manual id=no-token
import urllib.error, urllib.request

URL = "https://agent-preview-5sjqaty6ga-zf.a.run.app"   # the instructor's service


def status(path, token=None):
    """The HTTP status Cloud Run answers for a GET, with or without an identity token."""
    headers = {"Authorization": f"Bearer {token}"} if token else {}
    try:
        with urllib.request.urlopen(urllib.request.Request(URL + path, headers=headers), timeout=60) as answer:
            return answer.status
    except urllib.error.HTTPError as refused:
        return refused.code


print("no token:  ", status("/list-apps"))
```

Check who is exempt: a PostgreSQL superuser always bypasses the rules, and a table owner does too
unless the table is `FORCE ROW LEVEL SECURITY`. A copy of the data in a table with no rule is a way
around it.

## Personal data in the trace

A trace holds every prompt and every tool result: that is why it is useful, and why a trace of a real
conversation is personal data. In production, turn message content off
(`ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false`, or OpenInference's `OPENINFERENCE_HIDE_INPUTS` and
`OPENINFERENCE_HIDE_OUTPUTS`) or restrict who may read the traces, and remember that whatever the
service prints lands in the project's logs.

## What to ask for

You need five things from other people, asked for precisely.

<table>
<thead><tr><th>Ask for</th><th>Of whom</th><th>Why</th></tr></thead>
<tbody>
<tr><td><b>(a)</b> A model endpoint reachable from where the code runs, and a service account allowed to call it</td><td>the cloud platform team; security, for the location</td><td>The agent calls the model on every turn. A service account replaces a personal login or a key file.</td></tr>
<tr><td><b>(b)</b> <code>google-genai</code>, <code>google-adk</code> and a database driver from an approved package index</td><td>whoever runs the package mirror</td><td>Building the image runs <code>pip install</code>; many networks cannot reach the public index.</td></tr>
<tr><td><b>(c)</b> Read access for that account to a small, documented slice of the warehouse</td><td>the warehouse owner, and the data's owner</td><td>The account's rights are every caller's rights.</td></tr>
<tr><td><b>(d)</b> Somewhere to run a container with its own identity, private by default</td><td>the cloud platform team</td><td>No key file, and the list of who may call it is set there.</td></tr>
<tr><td><b>(e)</b> A place for traces, with message content off or access restricted</td><td>the platform team, and security</td><td>The steps contain prompts and results.</td></tr>
