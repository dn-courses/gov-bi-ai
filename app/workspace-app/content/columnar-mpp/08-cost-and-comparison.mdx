query. So the cost of a query is decided when it is written, and it is part of the design.

A helper that turns a dry run's bytes into dollars, and that query's price:

```python
PRICE_PER_TIB = 6.25          # BigQuery on-demand, US

def dollars(gb):
    """The on-demand price of reading this many GB (10^9 bytes, as the dry run reports them)."""
    return gb * 1e9 / 2**40 * PRICE_PER_TIB

print(f"monthly average, 46.1 GB: ${dollars(46.1):.2f}")
```

In PostgreSQL, rolled back so the table stays as it was:

```sql needs=station-index
BEGIN;
EXPLAIN (ANALYZE, BUFFERS)
UPDATE station_status SET bikes_available = 0
WHERE station_id = 42 AND captured_at = '2026-08-01 12:00:00+00';
ROLLBACK;
```

In the Parquet file, the only way: write all of it again with the one value changed.

```duckdb id=rewrite
COPY (
  SELECT * REPLACE (CASE WHEN station_id = 42 AND captured_at = TIMESTAMPTZ '2026-08-01 12:00:00+00'
                         THEN 0 ELSE bikes_available END AS bikes_available)
  FROM 'station_status.parquet'
) TO 'cost_changed.parquet' (FORMAT parquet);
```

```bash needs=rewrite
ls -l station_status.parquet cost_changed.parquet
rm -f cost_changed.parquet
```

</Step>

An application does those two things thousands of times a second, and needs them correct when two
happen at once. Most organisations run both kinds of store, and copy data from the first into the
second.
