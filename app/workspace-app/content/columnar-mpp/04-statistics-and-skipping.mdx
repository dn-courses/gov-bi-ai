The whole quarter of station readings is one Parquet file of 25,920,000 rows. Ask it about one day.

<Step>

The footer's entries for `captured_at` and `station_id`, in the first three row groups and the last:

```duckdb
SELECT row_group_id, row_group_num_rows AS rows, path_in_schema AS column_name,
       stats_min_value AS min, stats_max_value AS max
FROM parquet_metadata('station_status.parquet')
WHERE path_in_schema IN ('captured_at', 'station_id')
  AND row_group_id IN (0, 1, 2, 210)
ORDER BY row_group_id, column_name;
```

The file was written station by station, so each row group holds a few stations' whole quarter.

<Step>

Write the same rows sorted by time into a copy of this page's own, with the newer Parquet writer
(`PARQUET_VERSION v2`). It takes about three seconds.

```duckdb id=sorted
COPY (SELECT * FROM 'station_status.parquet' ORDER BY captured_at, station_id)
  TO 'statistics_and_skipping.parquet' (FORMAT parquet, PARQUET_VERSION v2);
```

The same check on the copy, and the spans of the row groups around 1 August:

```duckdb needs=sorted
SELECT count(*) FILTER (WHERE stats_min_value::TIMESTAMPTZ <  TIMESTAMPTZ '2026-08-02 00:00:00+00'
                          AND stats_max_value::TIMESTAMPTZ >= TIMESTAMPTZ '2026-08-01 00:00:00+00') AS may_hold_the_day,
       count(*) AS row_groups
FROM parquet_metadata('statistics_and_skipping.parquet')
WHERE path_in_schema = 'captured_at';
```

What the sort did to the columns that followed the station:

```duckdb needs=sorted
SELECT path_in_schema AS column_name,
       round(sum(total_compressed_size) FILTER (WHERE file_name = 'station_status.parquet') / 1e6, 1) AS station_order_mb,
       round(sum(total_compressed_size) FILTER (WHERE file_name = 'statistics_and_skipping.parquet') / 1e6, 1) AS time_order_mb
FROM parquet_metadata(['station_status.parquet', 'statistics_and_skipping.parquet'])
WHERE path_in_schema IN ('station_id', 'system_id', 'name', 'legacy_id')
GROUP BY 1 ORDER BY 3 DESC;
```

```python needs=sorted
import os

for f in ["station_status.parquet", "statistics_and_skipping.parquet"]:
    print(f"{f:34} {os.path.getsize(f) / 1e6:4.0f} MB")
```

The copy is smaller overall because the v2 writer encodes the sorted times far smaller; the same
writer in station order makes a 33 MB file, so sorting by time costs about 20 MB.

A warehouse holds the same kind of files, by the thousand, and charges by the bytes a query reads.
