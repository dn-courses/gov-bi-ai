## A container is not a small virtual machine

<Scene widget="ramp-stack">
<Step>
</Step>
<Step>
</Step>
<Step>

The app container, where `bash` cells run:

```bash
uname -r
ls /proc | grep -c '^[0-9]'
```

The second line counts the processes this container can see: a handful, not the hundreds running
on the laptop. Now the database container, asked through SQL for the same kernel file:

```sql
SELECT trim(pg_read_file('/proc/sys/kernel/osrelease'), E'\n') AS database_container_kernel,
       split_part(version(), ' on ', 1) AS and_what_is_installed_there;
```

</Step>

one command and be removed:

```sh
time docker run --rm pgvector/pgvector:pg16 true
docker images
```

## Before the first lab

Two commands tell you whether a laptop is ready. Both run in your own terminal:

```sh
docker version
docker run hello-world
```

<table>
  <thead><tr><th>You type</th><th>What happens</th></tr></thead>
  <tbody>
    <tr><td><code>docker version</code></td><td>Docker is installed and its engine is running: a Client and a Server section both print</td></tr>
    <tr><td><code>docker run hello-world</code></td><td>an image is downloaded, a container starts from it, prints a greeting and exits</td></tr>
    <tr><td><code>just present</code></td><td>the course's containers start; the pages open at <code>localhost:3000</code></td></tr>

    <tr><td><code>docker compose logs app</code></td><td>what a container printed — the first place to look when a page does not load</td></tr>
